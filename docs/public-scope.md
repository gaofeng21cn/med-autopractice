# 公开范围与部署边界

Med Auto Practice 公开仓库提供通用临床工作流合同、任务状态模型、合成数据处理和参考实现。它用于讨论工程规范与复核边界，当前不提供可直接用于真实患者任务的临床能力。

## 可以进入公开仓库的内容

- 通用领域模型、任务状态、审阅门槛和失败恢复语义
- 与医院产品无关的 schema、适配器接口、工作流合同和只读检查工具
- 合成患者、合成站点和合成操作结果
- 不依赖现场资料的测试、示例和技术文档
- 公开标准、公开协议和已获许可的第三方参考

## 由部署方私有管理的内容

- 医院、科室、系统厂家、产品版本、内部地址和账号角色
- 门户路径、窗口标题、按钮文字、页面坐标、等待条件和现场 playbook
- 患者、就诊、病历、医嘱、截图、OCR、操作 trace 和医生验收记录
- 院内制度原文、药品与检查字典、真实规则包和资格证据
- 密码、Cookie、token、证书、连接配置和任何私有运行日志

部署 profile、site survey、playbook 和证据存放在部署方受控目录中。`.gitignore` 只负责降低误提交概率，不能替代访问控制、加密、备份和保留政策。真实部署资料不能通过改名、打码或匿名化后回填公开仓库。

## 公开仓库的能力边界

公开版本中的能力目录保持 `planned` 和 `callable=false`。源码可读、测试通过、插件可安装或观察到某个系统页面，都不能单独证明医院系统适配、临床资格、医生授权或正式病历写入已经完成。

真实部署必须单独完成系统盘点、数据处理审批、权限核对、界面资格、目标对象回读和医生验收。部署方可以复用公开合同，但应把现场事实保存在自己的私有 owner 中。

## 提交前检查

提交前运行：

```sh
python3 scripts/public_release_check.py
python3 scripts/project_status.py --json
python3 scripts/package_metadata.py
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

发布时从干净克隆检查可达历史，并人工复核文档、合成样例与图片。自动检查覆盖常见凭据格式、内网地址、私有配置路径与未审查的二进制资源。
