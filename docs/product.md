# 产品定位与已确认范围

本页定义产品范围。技术集成进展见实施路线图。

品牌：**Med Auto Practice（MAP）**；中文定位：临床工作 Agent。名称中的 Practice 指医疗实践，覆盖门诊、住院、医嘱和文书；与 Med Auto Science（MAS）、Med Auto Grant（MAG）形成家族分工。未开展商标、域名或软件包名称可用性核验。

MAP 将医学提案、业务工作流和医院系统适配组织在一个智能体内。医生在 Codex 中说明意图、审阅草稿并查看差异，执行由任务内核和站点适配器承担。[架构与职责](architecture.md#模块与合同归属)

部署团队按每项操作选择获准的原生 API、中间件、直接 Computer Use 或 IP KVM。首批试点围绕住院病程草稿和医嘱调整。医生在提交前按批确认医嘱，提交后查看目标系统回读并验收。界面路径另需验证中文长文输入。[医院适配指南](hospital-adapters.md)

## 一期必须覆盖

1. 既往门诊与住院病历数据收集、结构化、完整性及来源核对。
2. 门诊与住院医嘱组套建立、动态更新、版本审阅与发布流程。
3. 新收患者医嘱草拟、医生确认后的录入与核验。
4. 结合检验检查结果、护理记录形成医嘱调整提案和确认后的更新。
5. 出院带药医嘱生成、用药核对和确认后的录入。
6. 住院日常记录：按实际临床事件和现行制度完成相应记录草稿、复核与回填。
7. 门诊结构化病历：完整记录已知关键信息，明确待补项。
8. 出院后病历整理、审核、修订提案和时效提醒。

当下工作为主线，既往整理是一期完整交付内容；不要求先迁移全部历史病例再开始当前工作。专病队列建立、数据整理和动态随访列入后续阶段，不阻塞一期验收。具体输入/产物与复核见 [工作流](workflows.md)，阶段状态由 [能力目录](../contracts/capabilities.json) 维护。

## 产品分工

MAP 管临床任务与证据，医院系统管正式医疗记录及医嘱状态，医生管临床决定和正式签署。MAS 的科研分析、MAG 的基金申报不在 MAP 一期范围内。未来研究型队列在合适授权下形成数据交付，不让科研任务直接写临床医嘱。

普通资料查询、导航、归类和草拟可在既有授权内连续完成；医生复核应集中在可审阅的草稿和拟变更上，不对每个机械点击重复询问。没有独立 UI 不等于省略医生复核和结果回读。
