# 院内 KVM 界面适配与资格记录

此文档定义各部署的界面接入与验收方法，不保存具体医院的产品档案。站点 profile 必须保存在仓库之外；这里仅维护可复用的资格要求。首版通过可替换的设备适配器操作 Windows，不假设医院开放 API/CLI，也不安装 Windows 辅助程序。

设备通道可用不能替代本适配器的操作 trace、患者身份核对或系统回读；每项业务语义操作仍须针对部署 profile 独立验收。具体状态不写入通用源码仓库。

## 每个界面档案应记录

- 医院标识、产品与版本、环境、账号角色、显示分辨率及资格证据引用；产品改版、角色或分辨率变化后重新核验。
- 设备访问路径及其控制权交接方式；只记录必要配置引用，不把院内地址或账号写入本仓库。
- 页面入口与识别特征、患者唯一标识和本次就诊标识的显示位置、切换路径、分页/虚拟列表和时间范围。
- 每个语义操作的前置页面、唯一锚点、输入焦点、等待条件、预期状态、异常弹窗和退出路径；动作前使用新鲜画面，写入类操作的视觉保护包含患者标识与目标控件。
- 读取范围及完整性：查到、未查到、未查询、被拒绝、无法识别分别记录；检验结果、护理记录和当前医嘱缺页时不得进入医嘱写入。
- 保存草稿、提交医嘱、签署、撤销的真实效果，以及在列表重新打开目标对象、核对完整内容和获取一手截图的位置。签署与医嘱执行不由保存状态推断。

## 首批两条工作流

1. 当前住院患者病程：核对患者与住院号，读取必要既往资料、当前医嘱、结果和护理记录，形成带来源草稿与待医生补充项。中文长文输入未通过非医疗 Windows 逐段准确性测试前，档案不得将 `write_inpatient_notes` 标为可写。
2. 医嘱调整：读取当前医嘱、相关结果和护理记录，形成具体新增、修改、停止清单及依据；医生对患者、就诊、事实版本和整批变更确认后，逐项录入。每项回读药品或检查名称、本地编码、规格、剂量、单位、途径、频次、时段及状态；不以按钮点击或 OCR 子串作为成功证明。

两条工作流的每一步关联任务记录与 KVM trace。医生最终看到从院内系统取得的一手截图和结构化差异，接受或提出修订；修订后重新回读。

## 硬件无关接入与中文长文输入三层策略

- **硬件无关 `KVMTransport` 抽象**：设备层通过统一 `KVMTransport` 接口屏蔽底层硬件差异，在继续支持 `glkvm-native`（通过配置或 OPL 包发现，不写死路径）的同时，兼容 PiKVM / JetKVM / NanoKVM HTTP+WS 网关及通用 VNC/HID 后端，确保其他医院无需绑定单一硬件型号。
- **中文长文输入三层策略（B 优先兜底 / A 可选插件 / C 降级底线）**：
  - **策略 B（一等兜底，优先完善与验收）**：纯 HID 键盘/输入法分段注入（按标点或定长分段）配合每段局部 OCR 逐字回读校验及有限次自动退格纠偏。零院方软件侵入，不假设医院放开剪贴板或网络中转。
  - **策略 A（可选提速插件，按医院策略开启）**：当且仅当医院网络与设备策略明确允许时，通过 KVM 协议剪贴板或受控局域网中转页实现原子粘贴 + 局部 OCR 回读核验。
  - **策略 C（安全降级底线）**：任意站点在尚未通过非医疗靶机逐字一致率资格测试前，自动降级为 `draft_only` 交付可审阅草稿，严禁向院内病历系统写入未校验中文正文。

## 失败与恢复

画面、焦点、患者、就诊、账号角色、分辨率或界面版本无法确认时停止输入。人工暂停和接管使旧自动控制租约失效；恢复后重新取得画面与患者上下文。提交响应丢失时，以完整任务上下文在院内列表查找可见对象；零个或多个候选都保持 `execution_uncertain`，不得再次点击提交。截图和正文只写入院方认可的私有位置，Git 中仅保留合成样例与规则源码。

能力目录中的 `callable` 只能在相应界面档案、数据处理范围、目标对象回读、一手截图和医生验收都取得真实证据后逐项调整。现有合成测试和 KVM 连通性检查均不能代替该资格。
