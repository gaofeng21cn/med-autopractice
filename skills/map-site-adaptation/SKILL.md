# 帮医生把一项工作接入本院系统

从医生要取得的结果出发，比如「为了写病程，先取回这次就诊的一项检验」。你负责查看配置、选择接入方式、执行获准的验证并保留结果。沿用对话里已有的目标和连接信息。以下命令从本 Skill 上两级的插件根或显式指定的 `MAP_SOURCE_ROOT` 执行。

## 先看已有条件

1. 执行 `python3 scripts/site_plan.py --inspect`。若已知是单项操作，直接加 `--dependency read_lab_results` 等依赖 ID；若要规划整份病程或一批医嘱，直接加工作流 ID `write_inpatient_notes` 或 `revise_orders`。显式给出的档案用 `--profile <文件>`，否则由工具读取宿主的 `MAP_SITE_PROFILE`。输出区分通用模板和外部档案。路径失效时修正所选档案，保留原配置。
2. 有档案就沿用它。只看本次操作的通道、证据引用和资格范围，核对当前角色、系统版本及授权是否仍适用。接口、证据或可访问的测试连接已经给出时，直接推进那一步。只有模板时先看用户是否已给过本院档案或可用入口。用户给了仓库外的部署位置且需要建立档案时，执行 `python3 scripts/site_plan.py --init-profile <新文件>`，随后用 `--profile` 重新读取。同一部署以后可由宿主设置 `MAP_SITE_PROFILE` 复用。公开示例的档案名为 `demo-mixed-transports`，证据使用 `demo://` 引用。遇到演练档案先辨认本次任务范围，现场验证应使用本院选定的档案与证据。
3. 目标或连接仍缺失时，只问一个决定下一步的问题。只说“启动”可问“你想先整理手头的病历，还是从本院系统取一项资料？”已明确想取检验结果且已有中间件，就只确认还缺的测试连接或测试对象。不要让医生填写整院调查表、提供密码或代跑你能执行的命令。

## 选择并验证一个操作

验证新的读取路径、复用旧操作手册或排查结果缺口时，先读随包的[院内系统适配与只读取数经验](../../agent/knowledge/site-adaptation.md)。按当前任务使用对应的身份、覆盖和回读检查，已有操作在角色、版本和范围仍适用时复用。

- **原生接口或院内中间件。** 先看医院已有且获准的 API、SDK 或集成平台。沿用其授权连接，核对患者与就诊标识的映射。若接口提供 FHIR R4 的已知 Encounter 和定量 Observation，可用随包的 `FHIRObservationSource.read_quantity` 验证一项结果，核对数值、比较符、单位、状态、时间及来源版本。其他协议依据实际接口合同，通过站点的 `ClinicalSystem` 映射为同一任务所需的数据。手头只有协议说明时可据此写适配代码或用合成响应验证映射，并标明下一步需要哪项现场证据。[医院接入示例](../../docs/hospital-adapters.md) · [适配器开发](../../docs/adapter-development.md)
- **界面操作。** 复用获准的浏览器或桌面会话，通过直接 Computer Use 定位患者、就诊和目标控件。隔离终端仅提供视频与键鼠时可选 IP KVM，连接与人工接管交给设备服务。按需调用 `scripts/site_survey.py`、`scripts/site_playbook.py` 读取私有调研记录与操作步骤，核对目标窗口、界面状态和回读对象。长文本输入、草稿保存及医嘱提交分别验证。[站点调研和操作档案](../../docs/site-survey.md)
- **在约定范围内试一次。** 使用站点批准的测试环境、测试身份和对象。逐项核对从原系统读回的事实，保留证据引用。对于写入，须另有该操作的授权，使用对应测试工作流审阅确切提案、受控提交并独立回读。一次只读测试只支持本次读取。没有可调用的站点提供者时，说清缺少的入口，同时继续完成用现有资料能做的部分。

## 带着结果回到原任务

在站点选定的外部档案中，只更新本次操作的 `transport`、`state` 和已有的证据引用。写前重读，保留其他操作和近期修改。实际观察记为 `observed`。站点对该角色、版本和操作完成资格审查，并取得独立的 `qualification_ref` 后才记为 `qualified`。凭据由连接提供者保管，患者资料与证据正文留在院方批准的存储。合成结果单独保留在演练目录。[部署档案](../../docs/site-integration.md)

重新运行针对这项操作的检查，核对保存的通道、状态和引用。向医生说明已经能用的来源、能交付的结果，以及还需谁补哪一步。若原目标是写病程，带着获准取回的资料继续整理草稿。若原目标是接入测试，交付本次结果和下次如何复用。单项依赖和整份临床工作流的开放分别依据站点证据与[能力目录](../../contracts/capabilities.json)判断。


## 接通已选站点

当部署方已经提供了获准的接口资料、测试会话和存储位置，先把本任务需要的字段、原对象身份、读取范围及写后核对映射到 `SiteProvider`。可在站点目录维护私有 `provider.py`，沿用现有连接和身份认证，确认 `authorize`、条件写入与回查均从实际系统或权限服务读回。用合成站点的同一入口验证本次配置和工作流。临床数据接入后，以部署方确认的规则和实际验收证据更新对应依赖，后续任务通过 `--site` 复用已批准的目录。[站点装配与验收](../../docs/local-deployment.md)
