# 院内系统适配与只读取数经验

医生交办一项工作后，先找完成它所需的第一项院内事实和已获准的连接。把每一步写成可核验的临床操作，例如“读取本次住院的当前医嘱”。一个操作的复用记录应写清适用范围、如何识别目标、如何确认成功以及失败后从哪里继续。

## 从单次就诊验证取数

1. **确认对象和范围。** 进入业务页面后，用源系统的患者与就诊唯一标识核对当前对象。切换系统、刷新后重新进入或发生人工接管时，再核对一次。姓名、床号和列表排序可帮助定位候选，身份以唯一标识为准。
2. **按操作选择入口。** 优先用已经获准且能返回所需对象、字段和版本的原生接口或中间件。需要通过界面补取时，使用已获准的浏览器或桌面会话。只有视频和键鼠通道可用时，复用站点指定的 IP KVM 服务。
3. **验证读取的覆盖。** 记录查询条件、时间范围、筛选、分页或滚动终点，以及来源对象、状态和观察时间。列表只显示一部分时，先检查后续页、虚拟列表或生效的筛选。来源无法读全时返回已读范围和缺口。需要确认阴性事实时，核对源对象的明确记录。
4. **核对业务对象。** 从文书列表打开目标文书，核对标题、就诊、状态和正文。读取当前医嘱时核对生效状态与时间，区分现行条目、历史记录和作废条目。检查文书时效时同时核对触发事件、文书状态和站点认可的时限规则。保留原系统引用，方便医生定位需核实的内容。

## 让界面操作可以复用

- 把导航分成“观察当前状态、定位唯一控件、执行一步、等预期状态出现”四步。使用宿主可访问的控件或稳定文字。视频界面先看局部文字及范围，在读不清或需要留证时再取图。界面改变、锚点多义或等待超时时，从可确认的页面重新定位。
- 在私有 playbook 中记录成功后的可见状态和失败策略。遇到门户登录、角色选择或人工接管，沿用宿主和站点的认证流程，恢复后核对当前账号角色及页面。来自手册或其他部署的步骤先按未验证记录，观察并重复通过后再更新状态。
- 调研档案中已合格的步骤可作为接入候选。把本任务所需的事实字段、覆盖范围和来源引用映射到该站点的 `SiteProvider`，经站点复验后更新运行时使用的依赖资格。独立验证读取、草稿保存、写后回读和正式提交。提交应答丢失时，从原系统回查同一对象。回查无法定位唯一对象时，保留待核对状态。

**合成演练。** 为示例住院 `SYNTH-ENCOUNTER-001` 读取当前医嘱。第一页显示若干条目并提示还有下一页，先保留已读条目并标出范围未完整。继续核对后续页的身份和筛选，直到确认结束，再记录总覆盖范围与来源。切换到文书系统时重新核对这次就诊的标识映射。两边身份不一致时，保留已读取的范围，暂停该操作并报告差异。

沉淀新的经验时，把跨站点成立的信号、检查方式及处置动作写进本知识条目，用全新合成情境说明。机构信息、页面路径与真实证据留在各自的私有部署档案。
