# 历史病历整理与研究数据复核经验

整理启动时先确认医生要的是病例审阅、跨病例数据表，还是还要回院内系统补资料。有采集包时直接复用。需要补取时，从有明确来源和缺口的文书开始，每条资料保留对应就诊、文书来源、时间和查询覆盖范围。

## 从采集包到可审阅病历

- 依据输入格式选择处理链路。采集包走 `scripts/structure_record.py` 的清洗和导出流程。手头已有结构化病历 JSON 时，按其合同校验，研究表层可直接消费该 JSON。
- 保留每次就诊的事实。对查询未覆盖、文书未记录、明确否认和识别不清分别标注。跨文书时间或内容冲突时，把双方的原记录和来源一起交给医生。入院、出院诊断分阶段记录，文字归并后的差异交由医生核实。
- 审阅按“结构化病历 → 问题与待核实项 → 采集范围内的原文”展开。在有争议的行或段落上放复核注记。问题清单说明差异和可核对的来源，便于医生直接定位。

## 导出研究长表前后的检查

- 保留原始措辞和归一化字段。抽查用药剂量、单位、途径和频次，以及日期、年龄、住院日等派生项。日期有不同精度时按共同精度比较。日期以对象形式保存时，按字段合同读取日期值再计算。
- 打开实际导出的 CSV 和阅读稿，抽查表头、样例值、布尔值显示及复核标注。审阅稿展示可核对的病例重点，九张固定列长表以 CSV 产物为准。
- 每例或每次导出使用独立输出目录。同一目录再次导出会覆盖固定文件名。跨病例合并前先核对列头、字段语义与关联键，再按表纵向合并。研究编号用于关联，真实来源正文和带标识的资料继续留在获准存储。公开示例从头构造合成病例。

**合成演练。** 两份示例文书记录同一事件，一份只到分钟，另一份记录了该分钟内的秒数，保留两条来源并按共同精度核对。另有两份同精度记录的分钟不同，把差异列入待核实项，并将标注落到对应行。导出后同时检查阅读稿和 CSV 中的时间字段。
